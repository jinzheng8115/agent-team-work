# 角色预设

继承 project-session-team-bootstrap 的三套模板。每套另有当前会话担任 Leader，负责目标、调度、验收与最终交付。成员数量、名称、职责和阶段可以在菜单中调整；每个 label 唯一。

默认标题为“项目名 · 角色显示名称”；Leader 为“项目名 · Leader”。以下顺序是初次派单顺序，返修可再次派给原成员。

## 全栈开发

先询问用户是否把开发拆成后端与前端；Agent、模型和 skill 不从模板静默预设。

**未拆分：**

| 顺序 | label | 显示名称 | 任务与交付 |
| --- | --- | --- | --- |
| 1 | product-architect | 产品架构 | 明确目标、用户流程、领域边界、技术方案，交付决策摘要与完成标准。 |
| 2 | developer | 开发 | 按已验收方案实现最小可运行版本，交付代码、运行方式和验证结果。 |
| 3 | reviewer | 质量审查 | 核对需求覆盖、回归风险、复杂度与验证证据，给出按优先级排序的问题。 |

**拆分：**

| 顺序 | label | 显示名称 | 任务与交付 |
| --- | --- | --- | --- |
| 1 | product-architect | 产品架构 | 明确目标、用户流程、领域边界、技术方案，交付决策摘要与完成标准。 |
| 2 | backend | 后端开发 | 实现最小后端路径、必要持久化、输入校验与错误处理，交付契约和验证说明。 |
| 3 | frontend | 前端开发 | 按已验收契约实现界面并核验交互，交付运行方式、视觉证据和边界。 |
| 4 | reviewer | 质量审查 | 核对需求覆盖、回归风险、复杂度与验证证据，给出按优先级排序的问题。 |

## 后端/API

| 顺序 | label | 显示名称 | 任务与交付 |
| --- | --- | --- | --- |
| 1 | api-designer | API 设计 | 定义资源、接口、错误语义与兼容边界，交付接口契约。 |
| 2 | backend | 后端开发 | 实现 API 和必要持久化，交付输入校验、错误处理与验证说明。 |
| 3 | api-reviewer | API 审查 | 检查契约一致性、安全和回归风险，交付阻塞项与修复建议。 |

## 研究与方案

| 顺序 | label | 显示名称 | 任务与交付 |
| --- | --- | --- | --- |
| 1 | researcher | 研究 | 收集事实、方案和约束，区分证据与假设，交付带来源的笔记。 |
| 2 | verifier | 事实核验 | 核验关键结论和来源，交付矛盾、证据缺口与核验结果。 |
| 3 | synthesizer | 方案综合 | 根据已核验材料比较选项，交付建议、取舍与行动清单。 |

## 自定义

建议 2–6 名成员，每个成员只承担清晰的主要职责；人数只是建议。菜单确认各成员的顺序、输入、完成判定和修改范围。高级运行设置使用宿主默认，用户明确指定时再核对支持的选项。

创建时全部待命，不提前发送后续阶段工作。审查发现问题后由 Leader 向负责成员派发返修任务，复核通过后才继续。团队总目标未满足时，不能因模板的最后一名角色已经回复就宣告完成。
